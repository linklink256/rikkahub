# TB373FU 定向低内存策略（2026-10-28）

## 目标与边界
仅针对用户当前TB373FU / aarch64 / Android16 / Linux6.1.157-Pessimistic验证；ART heapgrowthlimit256m、largeHeap上限512m。
采用固定的小缓存/快速回收/有限批处理策略，不建立其他设备兼容矩阵。仍是App层优化，不是内核补丁。
未修改系统LMK、zRAM、vm参数、全局堆上限，不依赖root常驻、不强制GC、不删除用户历史、不杀正式聊天进程。
不能把本轮称作“内存极限已达到”或所有场景已稳定。

## 已部署的改动
1. OpenAI ChatCompletions/Responses、Claude、Google请求：JsonElement经encodeToStream直接写OkHttp sink。
   exact Content-Length由计数OutputStream计算并缓存，body可重放；不生成整份UTF16 JSON String和UTF8 byte[]。
   计数需要再遍历一次JSON，换CPU时间减少堆峰值，JsonElement/原消息仍会驻留；不是零拷贝网络或无内存上限。
2. 长流相邻TextDelta/ReasoningDelta兼容时批处理；前4096字符保持即时预览，之后80ms到达检查/8192字符阈值。
   ID、metadata、reasoningType不同及所有结构/工具/用量事件强制边界；不丢文本、用量或工具顺序。
   没有独立计时器：若服务端暂停，残余等待下一事件或结束；取消时通过专用interruptedStep回调保存待发尾段，不在取消Flow中跨context emit。
3. Placeholder无左花括号的整段直接复用；只解析实际包含的placeholder，避免反复替换/系统resolver。
   Document转换器无文档时直接复用列表，无文档消息不复制parts。
4. 消息加载每页64行降为4行，减少同时驻留的JSON行；取消原来“异常时跳过整页”的行为，改为明确失败、DB不变，避免看似加载成功实则丢历史。
5. 空闲无引用session回收延迟5s→1s；后台ON_STOP/系统onTrimMemory回调尝试persist/evict。
   运行中、持有页面/SSE引用或队列未空的会话不回收，保存失败保留唯一权威状态。
6. Coil内存缓存固定24MiB，取消交叉淡入避免同时保留旧新图层。错误列表最多32条。
7. 前几轮Markdown显示分段、增量节点/FTS保存、末消息团队预览与队友权限/并发修复继续保留。
